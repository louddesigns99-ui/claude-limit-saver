# Set up a scheduled task without draining the limit

Scheduled tasks run while nobody's watching, so a wasteful one burns usage every day.

1. **Write the procedure first.** A short file with numbered steps, hard rules ("never send",
   "max 15 a day") and the report format. A good procedure lets a lighter model do the job.
2. **Pick the model explicitly.** Default tier for most runs (following a procedure, drafting from
   templates, checking data). Light tier for one-step mechanical jobs. Heavy tier only if the run
   needs real judgment every time. Never leave it on the account default.
3. **Prepare, don't send.** Unless the person has approved a specific standing action (what, how
   many, when, to whom), the task drafts and reports; the person sends.
4. **Short report.** Under 12 lines, most important first. No recap of the steps.
5. **Record it in CONTEXT.md** under "Scheduled tasks": name, when, model, what it may do.
6. **For long external jobs** (a build, another AI's research run), schedule one check-in later
   instead of checking repeatedly.
7. If you can't create the task with a tool in this session, give the person the exact prompt,
   schedule and model to enter themselves.
